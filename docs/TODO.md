- **时间自然流动（2026-10-22，已达成）**：用户要求「每过 5 秒等效 1 小时 → 两分钟一次日月循环」。
  - `js/weather.js:20` 新增 `SECONDS_PER_HOUR = 5`，`update()` 里的推进从 `dt / 3600`（真实速度）
    改成 `dt / SECONDS_PER_HOUR`。实测 10 秒 = 2.003 小时、120 秒整圈。
  - **日月轨迹补了两处逻辑缺口**（时间流起来以后每 2 分钟都会看见一次，所以必须修）：
    - 弧线两段同号 `x = 50 - 38 * cos(theta)`：**日月同向，都东升西落**（屏幕左缘 = 东、
      右缘 = 西）。月亮不因为「反日」倒着走 —— 满月只是与太阳相隔 12 小时，太阳在西边落下时
      它才刚从东边升起（2026-10-22 用户纠正过一版反向的实现）。
    - 交接那一次换位该怎么藏：日月共用同一个 DOM 元素，`rawElev = -0.5` 那一刻它的 x 必须从
      88% 跳到 12%（太阳西沉、月亮东升，这是天文事实）。做法是**两侧都淡到 0**——光球用
      2°/2.5° 窗口（`sunDisc` / `moonIn`），天光（日晕、炫光、月晕）用 6° 窗口（`skyVis`），
      交接点上日面和月面都不亮，换位就看不见。天光窗口不能跟着光球一起用 2°，否则 2 分钟
      一天的节奏下看起来是「啪」地关灯（`sun_smoke.mjs` 会以 0.5° 步长抓这个跳变）。
    - 月面的淡入淡出只能靠元素级 `opacity`（`--sun-disc-opacity`，写在 `.celestial.is-moon
      .celestial-disc` 上）：贴图本身不透明，`--sun-core-*` 的 alpha 只管得住兜底下层渐变。
    - 弧线进度改由真实的日出/日落时刻归一化（新增 `dayWindow(doy, latitude)`，时角公式
      `cos H0 = -tan(lat)tan(decl)`），不再写死 6..18。写死的话日盘会在画面边缘空转 0.36 小时
      （本纬度 10 月），换算成 2 分钟一天就是每次日出前卡住约 2 秒。
    - 月亮高度 `clamp(-rawElev - 0.5, 0, 74)`：减 0.5 是 `isNight` 的翻转阈值本身，不减的话
      交接瞬间日盘凭空上跳半个度（约 4px）。
  - 交互：拖动时间滑杆/拖动日月 = 暂停（`manualTime`）；轻点日月 = 跳到正午/午夜但**继续流动**；
    `AUTO` = 恢复流动（不再偷偷跳回真实时钟，那是 `RESET` 的活）；`RESET` = 回到此刻真实时间并继续流。

  - 数值证据：`_wip/verify/time_smoke.mjs`（60fps 推演 135 秒）——单帧最大横移 0.036%、纵移
    0.093%（≈0.7px），日夜交接处横移 0.002%、拖动反解误差 0.0000 小时，全部通过。

### 2.3 P0 动作（按顺序做，每步都要截图证据）

**a. 调色板从 3 段扩到 8 段**
- 按**太阳高度角**切关键帧，每段一组完整色：`top / mid / horizon / seaFar / seaNear / seaDeep / sun / glow`，
  新增 `warm`（地平线暖带强度）+ `warmHue`（暖带色相）。
- 建议档位：`-18°（蓝调结束）/ -12° / -6°（蓝调时刻）/ -2° / +2°（黄金时刻）/ +8° / +25° / +55°（正午）`。
- 落点：`GIFT/js/weather.js:75-91` 的 `P` 与 `resolvePalette()`（weather.js:145-157）。

**b. 换到线性光空间混合**
- 加 `srgbToLinear()` / `linearToSrgb()`，`mix()` 只在 linear 里插值，输出前转回 sRGB。
- 这是「过渡平滑」最关键的一步，成本可忽略（8 色 × 8 档，每帧几十次运算）。
- 落点：`GIFT/js/weather.js:72` 的 `mix()` 与 `resolvePalette()`。

**c. 天空渐变色标改为太阳高度驱动**
- 新增 CSS 变量 `--sky-stop-top / --sky-stop-mid / --sky-stop-horizon`，在 `applySky()` 里随高度写出。
- `.atmosphere` 的 `linear-gradient` 用这些变量替换写死的 22% / 39% / 47%（`styles.css:666-673`）。
- 注意 `--horizon` 是 26%、`weather.js` 里 `horizonY = 25.2`，**动色标不能破坏地平线对齐**。

**d. 太阳方位驱动的天光**
- `.sky-wash` 的两个高光改成 `at calc(var(--sun-x) ± k%) var(--sun-y)`（`styles.css:676-683`），
  强度用 `--warm` 控制，使晨昏天光跟着太阳方位走。

**e. 日盘按高度角查表**　`[已达成 2026-10-22]`
- 已落地：`SUN_LOOK`（`weather.js:260`）8 档（−4 / −1 / +2 / +6 / +14 / +26 / +45 / +70°），
  每档给 `core / a / a1 / bloom / ba / spread / flat`，`lookFor()`（`weather.js:274`）
  用 `smooth()` 在相邻档之间插值。
- **与原文相左的一处（以现实为准）**：原文写「低角度**变大**且压扁」，但真实的太阳视直径
  恒定（约 0.53°），变大的是光晕。所以尺寸固定 170px、由 `spread` 撑光晕，只保留压扁

- 另外：光晕用 `transform: scale()` 而不是 `filter: blur()`（跟太阳移动的大元素逐帧模糊太贵；

**g. 顶栏显示真实日出/日落时刻**

**h. 海面联动**

### 2.4 验收（做不到就不算完）

### 7.1 「空」不是靠填满解决的 —— 三条原理

空的感觉来自三件事同时成立：**没有光的方向、没有第二焦点、没有任何东西在动**。
所以三条一起修，而不是往空白处堆装饰：

1. **让光解释暗**：全场唯一光源是蛋糕上的十九支蜡烛。光照不到的地方就是暗的，不是「空白的布」。
   暗角不是遮丑，是物理结果 —— 这一条决定整张图的明度结构（§7.4）。
2. **给眼睛两个落点**：蛋糕在正中，对称构图本身是静止的。在三分点上放**罗盘玫瑰**和
   **手写台词**，视线才有第二站。**只填三个角，第四个角留空**（留空是设计，不是没做完）。
3. **让空的地方动起来**：刀影在布上扫过、刀尖到圆心那条方位虚线、光池随鼠标轻微偏移、
   十几粒浮尘 —— 空的地方一有东西在动，就不再有「一块布」的观感。

**一句话设计**：
> 幕布 = 一张铺满全屏的亚麻台布；唯一的光是十九支蜡烛，从蛋糕向四周衰减；
> 台布上印着一张潮汐海图，**蛋糕就是海图上那座岛**；**刀是罗盘指针** ——
> 所以刀尖永远指着圆心：这是罗盘的规矩，不是动画的随手设定。

### 7.2 「刀尖永远指向圆心」怎么解释才不别扭

这是全篇的钥匙。一条「永远指向中心」的线在画面上只有两种解释：**罗盘指针**或**钟表指针**。
选罗盘：站点叫 TIDELINE，卡片写的是坐标与潮位，海图上的指针指向的是**极点**。于是：

- 刀的**尖端钉在鼠标上**，刀身沿「鼠标 → 圆心」这条半径躺下；
- 鼠标绕蛋糕走，刀就**绕圆心扫一圈** —— 它是在转，不是在飘；
- 刀投在布上的影子永远背对蛋糕（光从蛋糕来），**影子把「空」填掉了**，而且是免费的。

### 7.7 刀的运动（三段速是硬要求）

入场：刀尖从屏幕下方沿**二次贝塞尔**进（控制点垂直于连线偏 140px，走弧线不走直线），
终点 = 鼠标位置投影到「距圆心 ≥190px」且距视口边 ≥80px 的那个点。

`T = 1400ms`，`u = t/T`，三相边界 `a = .28`、`b = .74`：

| 相位 | u | 位移 | 占全程 |
|---|---|---|---|
| 加速 | `0 – .28` | `s = v·u²/(2a)` | **19.2%** |
| 匀速 | `.28 – .74` | `s = .1918 + v·(u−.28)` | **63.0%** |
| 减速 | `.74 – 1` | `s = 1 − v·(1−u)²/(2(1−b))` | **17.8%** |

`v = 1/(a/2 + (b−a) + (1−b)/2) = 1/0.73 = 1.3699`（由「三段位移和 = 1」解出）。
1280 宽下行程 D≈900px → 峰值 ≈ 880px/s。**三段必须肉眼可分**，否则用户说的「不是匀速」没落地。

跟随（到达之后）：
- 位置阻尼 `20/s`，方位角阻尼 `14/s`，**角速度上限 220°/s**（超了像在甩鞭子），
  自然滞后约 70ms —— 这就是「有重量」的全部秘密。
- 刀尖与鼠标始终对齐；刀身朝向 = `atan2(cy − tipY, cx − tipX)`；
- 鼠标进到 r<190 以内时刀**不缩短**，而是沿半径把刀尖推到 190px 处（刀身永不出画）。

### 7.8 切开：一条线，同时切开蛋糕和幕布

1. **点击（0–90ms）**：刀沿自身刀轴刺入，刀尖越过圆心 46px；一个 1px 白闪 + 5–9 粒蛋糕屑
   （速度 90–260px/s，摩擦衰减 `6.5/s`，约 420ms 停住）。
2. **切口扩散（90–330ms）**：切口 = **过圆心、沿点击那一瞬刀轴**的那条直线
   （`cutAngle = atan2(cy − tipY, cx − tipX)`，所以**每次玩切口方向都不同**）。
   两个方向以 1.6px/ms 同时外跑；切口中先亮起 1–2px 的缝 —— **缝里透出来的就是海**。
3. **两半翻开（330ms 起，900ms）**：台布被切成两半，每半是**整个场景的一份克隆 + 半平面
   `clip-path`**（切口 24 段 ±2px 噪声，两半互补 → 看起来是撕的，不是激光切的）。
   翻开用 `transform: rotate3d(cosθ, sinθ, 0, ±30deg)`，铰链就在切口线上；
   父级 `perspective: 1400px`（`.intro` 已有 `perspective: 1700px`，`styles.css:145`）。
   同时沿法线各漂 12vw 并淡出。
4. **露出**：**不画假的「里面」** —— 台布后面本来就是活着的海（海面引擎的 canvas 一直在
   `.intro`（`z-index:50`）下面跑）。所以这一刀是真的刺破了幕布，**露出来的画面在动**。

### 7.10 时间轴

「画面上移」有两种读法：**A（推荐，成本低）= 台布从 `translateY(7%)` 升入归位**；
**B = 把现有封面（门）整体上移退场、台布从下方推上来**（换幕感更强，但要多一层克隆）。
下表按 A 写，B 只需把 0–1.1s 那行换成一个 `translateY(-100%)` 的旧层退场。

| 时刻 | 事件 | 时长 / 缓动 |
|---|---|---|
| 0.00–1.10s | 台布升入归位：`translateY(7%) scale(1.05)` → `0 / 1` | `cubic-bezier(.16,1,.3,1)` |
| 0.35–0.95s | 光池与暗角亮起 | 线性 |

**偏差 1（构图，已暴露为 §7.13 第 8 条）**：蛋糕圆心从设计稿的 47% 改到 **62%**，直径 336 → **300px**，
标题在台布在场时缩成印刷体抬头。原因：47% 与 300px 高的封面大标题重叠，
在 1280×800 下是无解冲突（算过：两者都要居中时，标题行高 0.72 的两行衬线字占 250–550px，
336px 的蛋糕占 232–568px）。`CY_RATIO = 0.62` 在 `GIFT/js/cakegate.js:24`，CSS 里五处圆心同步改成 `50% 62%`
（`.cloth-light` `GIFT/css/styles.css:3100`、`.cloth-vignette` `:3109`、`.cloth-chart` 遮罩 `:3122-3123` 与 `:3321-3322`、
`.cloth-half` 的 `transform-origin` `:3131`）。

**偏差 2（台布上的打字排没做）**：设计稿 §7.4 说台布上印坐标 / 「MMXXVI」/ 台词，
落地时没做——封面 `cover-content`（`GIFT/css/styles.css:376`）本来就压着这些字，
再印一遍是重复。若要「门退休」后把文案搬到台布，属于删除门那一步（§7.13 第 1 条），届时一起做。

**偏差 3（门的处置）**：CSS 用 `.intro.has-cake .door { visibility: hidden }` 隐藏，
**没有删** `GIFT/index.html:203-332` 那 118 行。等用户点头再删，删之前随时可回退。

**偏差 4（刀影）**：没有单独一层 SVG 影子，用刀体自身的 `drop-shadow` 一次画完。

**偏差 5（阻尼）**：设计稿写「方位角阻尼跟随」，落地是**精确指向**（每帧 `atan2` 直接对准圆心），
因为用户的原话是「刀尖始终指向蛋糕圆心」，阻尼会在快速移动时短暂偏离。实测轴误差 0°。

**修掉的两个真 bug**（都是自己验证时抓到的，不是猜的）：

1. **过早缝合**：滚回封面时，`gate` 从 1 落到 0 的全程都被判成「正在复原」，
   于是切开的台布在还没合拢时就开始缝合。修法：加 `sawGate` 标志，只有 `gate > 0.02` 之后进入的复原才算缝合。
2. **两半边缘不互补**：`cloth-half` 的 `clip-path` 用「噪声扰动的切线」做边界，但扰动量的符号跟
   `side` 绑反了，导致两半之间出现 1–2px 的白缝/叠边。修法：两半共用同一个噪声采样函数
   （`sharedNoiseEdge`），一边加、一边减，保证严丝合缝。
