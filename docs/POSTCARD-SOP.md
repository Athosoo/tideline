# 加一张明信片：固定流程

> 2026-11-01 立。起因：每加一张卡都要手动裁图、画背面、抄十几个字段、重建字体、
> 改散落在 HANDOFF/TODO 里的说法，耗时极长而机械易错。
> 现在：**一条命令做完机械活，人只负责「好看的图 + 不啰嗦的文案 + 最后目验」**。

## 0. 三条铁律

1. **一张卡在屏幕上的大小只由视口决定。** 素材像素尺寸、横竖朝向、所在深度都不参与排版：
   `js/app.js` 的 `cardFaceWidth(width, height)` 是唯一来源，`rebuildLayout()` 里所有卡共用
   `metrics.projected`，聚焦视图的宽度由 CSS 决定（横版拿同一个竖版宽度整体转 90°）。
   历史教训：以前按每张卡自己的素材网格取整数倍，120 网格的卡恒为 360，100 网格的卡在 300/400
   之间跳，同屏最大差 33%，而且换一次随机种子就换一套大小 —— 用户判为「大忌」。
2. **不要再往布局里塞「按素材对齐」的逻辑。** 想要更清晰就加大素材，不要动布局。
3. **文案字数就是版式。** 超了就会换行、压边；超限先改文案，不要靠调字号补救。

## 1. 一条命令

（在仓库根 `E:\DeepSeekplay` 下跑；`NN` 是两位卡号）

```
python _wip/verify/new_postcard.py --number 06 --front "D:/pics/a.png" \
    --title 相拥 --meta "黑白影像 · 竖版" --short "爱和拥抱，都拼好了" \
    --quote "「你抱着我，我才活着。」" --date 二〇二六
```

可选开关：`--back 原图`（不给就生成背面）、`--accent "#a08086"`（不给就取正面主色）、
`--landscape` / `--portrait`（画幅默认由原图长边决定）、`--pixel-art`（最近邻缩放）、
`--force`（覆盖已有图）、`--dry-run`（只看计划，不写不跑）。

## 2. 它替你做了什么

1. 正面图缩到**规范网格**：竖版 120×180 / 横版 180×120，写 `GIFT/assets/postcards/NN-front.png`；
2. 没给 `--back` 就按站内纸色 `#eee6d7` + Noto Serif SC 生成背面 `NN-back.png`
   （顶行 `TIDELINE` / `ED. NN`，引文居中，卡名与日期落在底，细线取 `accent`）；
3. 重写 `js/app.js` 里 `POSTCARDS` 的条目：字段顺序与缩进跟现有条目一致，
   `pixelWidth/pixelHeight/landscape` 按第 1 步的真实结果填；已有同号占位条目就**就地替换**；
4. `node --check js/app.js`，再跑 `python _wip/verify/cjk_font.py build` 重建内嵌中文字体子集；
5. 跑 `node _wip/verify/postcards_smoke.mjs`（张数/编号/文件/尺寸/画幅/index.html 引用）
   与 `node _wip/verify/card_size.mjs`（8 个视口 × 全部卡，屏幕宽度必须完全一致）；
6. 打印剩下的四件事（见 §5）。

## 3. 素材约定

- 一律 PNG、2:3；竖版 **120×180**、横版 **180×120**（画幅由原图长边决定）。
- 01 那种真像素画用 `--pixel-art`（最近邻）；照片一律 Lanczos（默认）。
- 老卡（02/04/05 的 100×150）**不用重导出**：尺寸已不参与排版，重导出只有成本没有收益。
- 背面每张可以不一样（01 是印刷背版式、05 是灰底居中英文）；没手绘的就用脚本生成，
  它是「体面的默认值」，不是标准答案，想换就 `--back`。

## 4. 文案上限（现有 7 张实测，脚本会超限报警）

| 字段 | 上限 | 说明 |
| --- | --- | --- |
| `title` | 6 字 | 卡名，长廊当前卡与聚焦大标题都用它；六个字有专门的字号档 |
| `meta` | 12 字 | 「校园 · 清晨六点五十五」这种 |
| `short` | 9 字 | 长廊底栏那一句 |
| `quote` | 19 字 | **含「」**，聚焦面板只排一行 |
| `date` | 6 字 | 「二〇二六」 |

`backAlt` 由脚本按 `明信片背面：{title}` 填。

## 5. 只剩人能做的四件事

1. **目验**：长廊里所有卡是否同宽（滚动一圈看边缘是否齐平）；点开第 NN 张看聚焦视图——
   引文是否单行、是否压边、横版转动是否正常。
2. **文案取舍**：脚本报「超限」时改文案，不是改字号。
3. **改文档**：脚本会 grep `占位|placeholder| NN ` 给出候选行（`docs/HANDOFF.md`、`docs/TODO.md`），
   逐条判断哪些说法过时了。
4. **提交**：`GIFT/` 里提交（commit 文案见 `.dsh/GIT_CONVENTIONS.md`），
   再在根仓库 `docs/WORKLOG.md` 顶部追加一条（日期/改了什么/为什么/`仓库@短号`/怎么验）。

## 6. 坑（都是踩过的）

- **不用改 `index.html`**：卡相关的静态引用只有 4 处（01 的 preload 与聚焦兜底 `img`），加卡不需要动。
- **06/07 现在是英文占位**（`06-front.svg` / `07-*.svg`）。用脚本填号时会替换 JSON 条目，
  旧 svg 顺手删掉即可。
- **字体子集忘重建不会报错**，只会让新字回落到系统宋体，字形在别人机器上跑偏。
  脚本已内置 build，手动改文案时别忘了。
- `_wip/cards.json` 是旧副本，不是真相，别照抄。
- 别把「整数倍对齐」改回来（铁律 1）。
